# Translation：配置驱动的客户报文转换

Qt 5.14.2 / C++11。用户在软件输入框中输入客户报文，程序只使用一个下游串口连接趋盛控制板。客户协议的格式与命令码均由配置决定，程序不预先知道 DT。

## 操作步骤

1. **客户协议格式**：选择 ASCII 或 HEX，填写帧头、帧尾和顺序字段。命令码可按固定长度读取，ASCII 也可选择“按命令码识别”。保存到草稿。
2. **命令映射**：选中一条，在下方填写客户命令，从完整趋盛指令池中选择目标，再设置参数来源或固定值。支持按中文名称、指令码搜索和按类别筛选；已有运动模板保留可选换算倍数，默认直接使用数值。保存到草稿。
3. **报文调试**：对于已支持发送的目标，输入完整报文，点击“预览但不发送”，查看原始输入、字段、映射、换算、统一命令和趋盛 HEX。标记“发送待实现”的映射可以保存，但不会生成目标帧。
4. **设备与连接**：核对板地址、电机编号、默认运动速度和行程，保存；校验配置、明确启用，连接下游，勾选设备参数确认。新动作的模式和方向由所选模板确定。
5. 回到调试页，点击“真实发送到下游”。查看实际发送帧、原始设备回告、解析结果、执行状态和中文错误原因。

编辑、保存、校验、启用是不同状态。顶部始终显示“当前草稿”和“当前已启用版本”。草稿修改后需要重新校验、启用和确认；在途请求使用原快照，不能在执行期间切换配置。

## 完整趋盛指令池

目录覆盖用户提供的《TW-RD-0XX功率驱动板通信协议 V0.1.7》3.2.1–3.2.56 全部 **56 类指令**，包括 **52 类可下发指令**和 **4 类仅设备主动上报的报文**。其中0x11在可选池中拆为四种动作，共59个选择项。每项均有中文名称、分类、指令码、参数说明及协议章节，详见[目录设计与完整清单](docs/command-catalog.md)。

0x11可选项为**步进电机前进、停止、后退、复位**，工作模式固定为绝对位置模式4，动作值分别为1、2、3、4。电机编号和速度来自设备默认参数，常用编辑只填写距离来源或固定值；绝对模式下距离数值直接作为目标位置，不对当前位置加减。前进、后退可预览和发送；停止、复位按用户确认暂只选择和保存，显示“发送待实现”。详见[四种动作设计](docs/motor-actions.md)。

“目录完整”与“发送已实现”分别表示不同能力。其他可下发指令仍可选择并保存参数映射；0x17、0x45、0xD9、0xE6 只用于接收说明，不能绑定为下发映射。已加载的旧绝对/相对映射保留原有行为，并标明兼容用途，不加入新建可选池。待实现指令没有通用 HEX 直发通道，也不会借用运动编码器。

参数编辑提供数字字段引用、固定数值；复杂结构、变长数据和协议有歧义的部分只提供说明，留待对应执行器实施。保存待实现草稿不要求提前完成这些结构；配置校验通过也不代表目录中每条指令都能执行。已支持映射可与待实现映射保存在同一配置中。

## 数值验证示例

默认加载 `examples/dt-simple-commands.json`。以下内容只是用户提供资料生成的**可编辑验证配置**，没有进入通用解析器的专用分支。

| 输入框中的报文 | 配置目标 | 反馈时机 |
|---|---|---|
| `/1A2000R\r`、`/1a2000R\r` | 新前进模板，绝对目标2000，0x11模式4/动作1 | A 接纳后；a 完成后 |
| `/1P500R\r`、`/1p500R\r` | 旧版相对前进500，保留位置模式2/动作1 | P 接纳后；p 完成后 |
| `/1D500R\r`、`/1d500R\r` | 旧版相对后退500，保留位置模式2/动作3 | D 接纳后；d 完成后 |
| `/1?\r`、`/1?0\r`、`/1?4\r` | 电机位置查询，0x12 | 收到查询回告后 |
| `/1&\r`、`/1?23\r` | 设备版本查询，0x04，请求数据0000 | 收到查询回告后 |

输入框用 `\r` 表示回车。新示例默认直接引用数值：输入 2000，目标也是 2000。**本轮尚未建立客户与设备物理单位的等价关系**；若以后需要换算，可在界面填写倍数或在高级配置保留精确关系。内部 `positionUm`、`distanceUm`、`speedUmPerS` 沿用趋盛线上单位约定，不能据此推断客户值已换算。

相对运动的预览显示运动帧；真实发送会先用 0x12 查询当前位置，确认空闲且计算终点未越界，再发一条运动帧。当前值未知、未回零、忙、查询超时或终点越界都不会发送运动。运动应答与动作完成仍分开判断。

上述相对流程仅用于旧配置兼容。新前进/后退不执行相对终点加减；客户命令码、大小写和数值关系仍由配置决定。`motor-actions.json` 是另一份自行定义客户格式的示例：`!F2000\r`、`!B1000\r`可预览，`!S\r`、`!H\r`仅命中停止/复位草稿并提示待实现。默认速度是随0x11运动帧发送的数据，不需要先发送独立速度配置报文。

资料冲突按用户确认以 HMD6 手册为主：`#/?20` 是固件校验码，趋盛没有等价项，暂缓；`?4` 使用电机位置，不用负反馈冒充；`?0` 是映射表的验证别名。版本查询显示趋盛版本，不模拟客户设备回包。详细差异见[分析与设计](docs/mapping-design.md)。

`dt-preview.json` 保留上一阶段单条绝对位置/十倍换算回归；`ascii-preview.json`、`binary-preview.json` 验证另外两种配置。它们可按需导入，不是本轮默认配置。修改帧头、帧尾或命令码无需修改 C++。

## 状态与边界

串口写出、设备接纳、动作完成不能合并。接纳反馈可先显示成功结果，但后台仍通过 0x12 确认空闲和本次目标后才释放运动请求。失败、超时和取消等待都不会自动重发运动。取消本地等待不会停止设备。

设备状态未知时可通过“查询设备状态”恢复；写出故障先重连。同一连接序号不回绕，256 个报文用完须重连。预览使用独立编码器，真实发送序号由请求管理器分配，因此以实际发送帧为准。

示例地址2、源地址1、DevID 0x11、速度1000、行程0–6000仅用于数值验证，尚未完成实机验收。用户已确认相对前进/后退方向，仍需实机确认参数和回告时序。

完整目录已包含阀、停止、通讯配置、初始化、动作集和固件更新等指令，本轮只实现其选择、说明和草稿参数编辑。执行器仍只支持上述单条运动和只读查询；混合指令、循环、TCP、位拼接、脚本和通用 CRC 编辑暂缓。
