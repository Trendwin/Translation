# Translation：配置驱动的客户报文转换

Qt 5.14.2 / C++11。用户在软件输入框中输入客户报文，程序只使用一个下游串口连接趋盛控制板。客户协议的格式与命令码均由配置决定，程序不预先知道 DT。

## 报文调试操作

软件用于串口报文调试，窗口标题为“配置驱动协议转换”。连接串口后填写客户报文，直接点“发送”；不用先保存、校验、启用或勾选参数确认。发送和手动查询按钮始终可点击，串口未连接或不能生成报文时显示具体错误。连续点击按队列逐条写出，不以设备忙闲或在途请求禁用按钮，不自动查询或重发运动。

发送读取当前格式、设备参数及已添加的映射；尚未点击添加的新映射不参与发送。生成临时快照，不自动保存配置、不改变已启用版本，软件字段范围及设备行程不参与调试发送限制；无法表示在协议字节中的值仍由编码器明确报错。

“预览”仍使用已保存配置；真实发送会重新解析当前输入并显示本次目标帧，不发送上一次预览。需要持久保留配置时再点击底部“保存配置”。配置默认保存在`%LOCALAPPDATA%/Trendwin/Translation/draft.json`，恢复不自动连接串口。

底部并排提供“保存配置、导入配置、导出配置”三个同尺寸按钮。顶部配置版本栏、省略字段勾选区及参数确认框已移除，高级配置页隐藏，主界面只保留四页。保存、导入及启动恢复时，软件自动检查并启用有效配置，不需要手动校验或启用。配置有误仍保留已保存内容并显示具体原因；修复后再次保存即可。复杂参数可通过导出JSON文件编辑后重新导入，原有扩展配置继续保留。详见[报文调试版说明](docs/packet-debug.md)。

命令映射页只提供添加、删除，表格不再联动编辑。点击已有行只选中删除目标；下方“添加新映射”始终是独立空白表单。填写客户命令、动作和参数后，点击表格下方、删除按钮旁的“添加命令映射”，只追加到表格末尾并清空表单。修改指令需先删除旧项再添加；客户命令重复时明确提示，不覆盖旧项。“保存配置”仅保存已添加/删除的结果，不提交尚未点击添加的表单。

顺序格式始终按字段表解析全部字段。停止、复位或查询的“不使用客户参数”仅表示映射不取用这些值，报文中的参数和分隔符仍必须存在并通过校验，旧映射无需重建。只有命令字段选择“按命令码识别”（mappedCommand）时，保留旧短报文省略规则，例如`/1ZR\r`或`!RST\r`。详见[格式与未使用参数](docs/format-driven-parsing.md)，通用示例为[format-driven-unused-parameter.json](examples/format-driven-unused-parameter.json)。

清单只通过“添加到清单”增加条目，选中后“保存本条修改”仅更新该条。“新增下一条”只进入草稿并保留动作和电机，重复点击不增加指令；未保存修改须保存或放弃，切换、移动和最终提交都不会自动补条。最终映射条数等于可见清单条数。上下表格可拖动分隔条调整高度，窗口放大时一起扩展。

停止和复位无需填写目标位置，SDK使用固定零位置；前进、后退即使不使用客户参数，也必须明确填写预设目标位置，不会自动填零。组内是否使用客户参数取值由“整组共用输入”统一设置。旧mappedCommand格式可试用[无参数双电机复位示例](examples/no-parameter-reset-group.json)：`!RST\r`依次复位0x11和0x12，`!FIXED\r`先复位0x11再让0x12前进到预设位置1234。

字段表中修改同一字段的名称时，参数来源和省略字段自动跟随全部映射。删除或改变字段作用/类型后，软件指出受影响的映射，不自动选择替代字段。需要持久保留时保存，调试发送无需校验和启用。详见[字段与映射联动](docs/field-adaptation.md)。

关闭窗口时，未保存的配置会提示“保存 / 放弃 / 取消”，默认取消。保存成功后关闭，保存失败保留窗口及修改；放弃不覆盖上次配置。仅修改调试报文不会触发配置修改提示。

界面面向熟悉趋盛协议的使用者，只保留核心编辑和调试控件。流程横幅、教学说明、协议详细说明、目录浏览和分类、偏移/取整控件、离线回告解析已从界面移除。日志不再占用公共区域。高级配置页隐藏；已有偏移、取整和精确分数关系随导入、保存、导出保留。详见[简洁界面设计](docs/expert-ui.md)。

## 顺序字段与分隔符

格式编辑恢复为原来的九列顺序字段表。长度方式新增“读到分隔符”，直接在同一列“长度 / 分隔符”填写`&`、`;`、`=`、`\n`等；读取字段后会消耗分隔符，继续下一行。固定长度、读取到帧尾、按命令码识别，以及原ASCII/HEX配置继续兼容。固定文字仍用固定字段，例如`END&`按4字节精确匹配。

不同命令码、可变序号与可变数值可使用同一张顺序表。参数的数据类型可选“整数列表”：`50`是一项，`20,200,3000`是三项。每条映射单独设置输入项数，取值来源下拉直接选“第N个参数”或固定值；缺项、多项、非整数均拒绝。仍不提供模板或样例生成模式。见[整数列表与逐项映射](docs/integer-list-parameters.md)，通用示例为`examples/integer-list-parameters.json`。

字段用途保留命令码、参数、固定字段，增加普通字段、执行控制（仅解析）、校验值（未校验）。只有整数“参数”可作为趋盛映射来源；等待、延时等执行控制仅供解析，转换发送会明确拒绝，校验值只提取并提示未校验。

“解析格式”按当前顺序表展示全部字段，不要求映射或设备配置、不生成目标帧。仅格式配置允许零条映射并可保存、重启、导入导出；“预览”及发送仍需要有效映射。`examples/delimited-single-parameter.json`可输入`[AA|BB|CTL|12|0;SET=255;10\nDONE|?|]\r`离线验证。

模板及样例编辑的两版入口和实现已移除。旧方案文件导入会明确拒绝，当前草稿与原文件保持不变。启动恢复此类旧草稿时只展示其保留的顺序字段，解析和发送均禁止；用户检查后显式“保存配置”才恢复为顺序格式，并将原`mode/textFormat`内容保留到`retiredFormatBackup`，不会读取时自动改写。详见[顺序字段说明](docs/sequential-fields.md)。

## 完整趋盛指令池

目录覆盖用户提供的《TW-RD-0XX功率驱动板通信协议 V0.1.7》3.2.1–3.2.56 全部 **56 类指令**，包括 **52 类可下发指令**和 **4 类仅设备主动上报的报文**。其中0x11在可选池中拆为四种动作，共59个选择项。每项均有中文名称、分类、指令码、参数说明及协议章节，详见[目录设计与完整清单](docs/command-catalog.md)。

0x11可选项为**步进电机前进、停止、后退、复位**，四种均可预览和发送。工作模式固定为绝对位置模式4，动作值分别为1、2、3、4。每条映射可选择电机编号0x11–0x16，选择“设备默认”时沿用SDK预置、设备参数或软件初始值；速度仍沿用默认；前进/后退映射绝对目标位置，停止/复位距离固定0，不要求客户距离参数。详见[四种动作设计](docs/motor-actions.md)。

“目录完整”与“发送已实现”分别表示不同能力。SDK已实现的普通指令可预览和发送，其他可下发指令仍可保存参数映射；0x17、0x45、0xD9、0xE6 只用于接收说明，不能绑定为下发映射。已加载的旧绝对/相对映射保留原有行为，并标明兼容用途，不加入新建可选池。待实现指令没有通用 HEX 直发通道，也不会借用运动编码器。

参数编辑提供数字字段引用、固定数值；复杂结构、变长数据和协议有歧义的部分只提供说明，留待对应执行器实施。保存待实现草稿不要求提前完成这些结构；配置校验通过也不代表目录中每条指令都能执行。已支持映射可与待实现映射保存在同一配置中。

## 单条趋盛SDK

已独立实现QtCore源码SDK，完整登记56族，当前31族单条控制/查询可组帧并解析回告。动作、事件、升级和复杂配置暂缓；C1已开放XYZ子类型，阀泵子类型仍拒绝；72保持布局待确认。软件映射直接调用SDK，不在客户解析器里添加某个客户协议的专用分支。

SDK未映射参数使用用户预置、设备参数或软件初始值；普通参数表保留“默认值、客户字段、固定值”三个选择。既有运动、字段改名联动、请求超时和下游串口模型保留。停止/复位已接入软件发送及状态跟踪，编辑时无距离控件。详见[SDK架构与使用](docs/qusheng-sdk-design.md)。

导入 `examples/sdk-simple-controls.json` 可验证风扇、阀、DAC、直流及查询，例如 `/1FAN50R\r` 只映射百分比，风扇编号由SDK预置补齐。SDK初始值不是厂家出厂配置；客户单位仍不自动换算。

## 数值验证示例

默认加载 `examples/dt-simple-commands.json`。以下内容只是用户提供资料生成的**可编辑验证配置**，没有进入通用解析器的专用分支。

| 输入框中的报文 | 配置目标 |
|---|---|
| `/1A2000R\r`、`/1a2000R\r` | 新前进模板，绝对目标2000，0x11模式4/动作1 |
| `/1P500R\r`、`/1p500R\r` | 旧版相对前进500，保留位置模式2/动作1 |
| `/1D500R\r`、`/1d500R\r` | 旧版相对后退500，保留位置模式2/动作3 |
| `/1?R\r`、`/1?0R\r`、`/1?4R\r` | 电机位置查询，0x12 |
| `/1&R\r`、`/1?23R\r` | 设备版本查询，0x04，请求数据0000 |

这份DT风格配置是统一帧尾的功能验证示例，所有命令均以 `R\r` 结束。原始DT查询不带R，另提供 `dt-query-preview.json`，帧尾统一为 `\r`，可输入 `/1?\r`、`/1?23\r`。原始DT运动与查询的不同结束格式不再通过映射覆盖实现。

输入框用 `\r` 表示回车。新示例默认直接引用数值：输入 2000，目标也是 2000。**本轮尚未建立客户与设备物理单位的等价关系**；若以后需要换算，可在界面填写倍数或在配置文件保留精确关系。内部 `positionUm`、`distanceUm`、`speedUmPerS` 沿用趋盛线上单位约定，不能据此推断客户值已换算。

报文调试中相对运动直接发送模式2/指定距离，不做当前位置前置查询；收到应答不宣告机械动作完成。底层非调试调用保留旧前置校验兼容逻辑。

上述相对流程仅用于旧配置兼容。新前进/后退不执行相对终点加减；客户命令码、大小写和数值关系仍由配置决定。`motor-actions.json` 是另一份自行定义客户格式的示例：`!F2000\r`、`!B1000\r`、`!S\r`、`!H\r`均可预览和发送；S/H由配置选择停止/复位并省略客户距离字段。默认速度是随0x11运动帧发送的数据，不需要先发送独立速度配置报文。

资料冲突按用户确认以 HMD6 手册为主：`#/?20` 是固件校验码，趋盛没有等价项，暂缓；`?4` 使用电机位置，不用负反馈冒充；`?0` 是映射表的验证别名。版本查询显示趋盛版本，不模拟客户设备回包。详细差异见[分析与设计](docs/mapping-design.md)。

`dt-preview.json` 保留上一阶段单条绝对位置/十倍换算回归；`ascii-preview.json`、`binary-preview.json` 验证另外两种配置。它们可按需导入，不是本轮默认配置。修改帧头、帧尾或命令码无需修改 C++。

## XYZ 虚拟模块

选择 `0xC1 | 虚拟模块控制（XYZ）`，分别设置虚拟模块编号和X/Y/Z位置；每项可以引用客户整数参数或填写固定值（包括0）。同一个客户参数可以同时供多个轴使用。三轴速度沿用设备页默认运动速度，未配置时SDK软件初始值为1000，不能据此认定厂家默认值；数值单位由下位机配置决定，不自动换算。物理电机与XYZ模块的绑定须预先在下位机配置，C2/C3及阀泵类型尚未开放。

通用示例 `examples/xyz-module-and-motors.json`：`!XYZ2000\r` 将2000传给X，Y固定0、Z固定66051；`!ALL2000\r` 将同一数值传给三个轴；`!M12000\r`、`!M22000\r` 分别控制0x12、0x13电机。模块编号不等于电机编号，物理电机停止不会取消虚拟模块请求。详见[XYZ配置说明](docs/virtual-module-xyz.md)。

## 状态与边界

串口写出、设备接纳、动作完成不能合并。0x11前进、后退、停止、复位及C1 XYZ控制收到有效应答后结束本地请求，显示“设备已应答，动作完成未确认”，不再自动发送0x12查询，不再等待30秒判定动作完成。需要查看状态时手动点击“查询状态”或发送已映射的查询报文。运动或未知状态仅供显示，不再限制下一次发送，也不要求先手动查询。等待应答时仍可点击发送，后续请求排队逐条下发。失败、超时和取消等待不会自动重发运动，取消本地等待不会停止设备。

同一电机执行中可输入映射好的停止报文并发送；软件终止原运动等待、取消同一电机尚未发送的运动，待正在写出的完整帧结束后优先发送停止。不同电机的停止不自动中断当前请求；复位在当前请求结束后发送。0x05紧急停止仍使用普通SDK请求路径，区别于此0x11停止模板。

设备状态未知时可按需手动查询，不影响继续发送；写出故障先重连。报文调试的8位序号循环使用，超过256条无需重连；序号循环后同地址同命令的旧迟到回告无法仅凭序号区分，调试记录不视为机械完成证明。预览使用独立编码器，真实发送序号由请求管理器分配，因此以实际发送帧为准。

0x12电机信息回告兼容文档的11字节DATA及实机的14字节DATA。14字节格式末尾D11～D13按保留位跳过，不要求为零；状态、当前位置和负反馈位置仍按原偏移解析。整帧长度、地址、序号和CRC检查不变，完整匹配回告可结束查询等待。

示例地址2、源地址1、DevID 0x11、速度1000、行程0–6000仅用于数值验证，尚未完成实机验收。用户已确认相对前进/后退方向，仍需实机确认参数和回告时序。

完整目录已包含阀、停止、通讯配置、初始化、动作集和固件更新等指令。执行器支持SDK已实现的31类单条控制、运动和查询；其余保留接口和草稿参数编辑。混合指令、循环、TCP、客户自定义位拼接、脚本和通用 CRC 编辑暂缓。

## 工程与文档

- `Translation.pro`：应用；`tests/tests.pro`：核心测试；`tests/ui-tests.pro`：界面流程及渲染测试。
- [配置说明](docs/config-schema.md)、[架构说明](docs/architecture.md)、[阶段范围与实机待确认项](docs/phase1.md)、[Windows 构建](docs/windows-build.md)。

物理步进电机按实际设备限定为六路0x11～0x16。旧超范围编号保留并提示重新选择，不能自动截成另一台电机；导入含非法物理电机编号的配置会拒绝且保留当前草稿。新增映射表单只添加新项，不修改上方已有项；“参数项数”只在转换预览/发送时校验，取值来源仍需明确选择“第几个参数”，不会自动生成多轴动作。

同一客户命令现可添加1～64条趋盛指令，允许重复、排序和每条独立参数来源。整组先检查，按前条成功应答且完整写出后继续，失败/超时停止剩余；ACK不表示机械动作完成。详见[一对多映射](docs/one-to-many-mappings.md)，通用示例为`examples/one-to-many-mappings.json`。调试页“取消本组”只取消最近组的本地等待和后续发送，不停止设备、不回滚已发动作；物理停止需独立停止命令。

电磁阀开关可在0x21直接选择“开启选中/关闭选中”并勾选阀号，单阀关闭无需手算位图；“覆盖全部”会关闭未选阀。0x22明确仅开启，编号显示为“1号阀（0x31）”，时间0不表示关闭。开启时间保留字段、列表项、固定值及默认来源。详见[电磁阀号选择](docs/valve-selection.md)，通用示例为[examples/valve-selection.json](examples/valve-selection.json)。

同一条客户命令通过参数决定开关时，在0x21选择“按客户参数开关（1开、0关）”，指定“开关参数”并勾选要控制的阀。收到1开启选中阀，收到0关闭选中阀，其余阀不变；其他值拒绝整组转换。示例中`!SW=1\r`和`!SW=0\r`共用同一个映射，分别开启/关闭1和30号阀。旧固定动作及无约束的高级控制方式来源维持原行为。
