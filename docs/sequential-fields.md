# 顺序字段与分隔符

本轮只保留原来的九列字段表，不提供模板、样例生成、参数组或另一种格式模式。已确认要接入的新报文都是单参数，命令码和参数值可变长。

## 在原表配置

在顶部填写共用帧头、帧尾与编码。字段从第一行连续读取，各行设置名称、作用、数据类型及长度方式：

| 长度方式 | “长度 / 分隔符”填写 | 读取行为 |
|---|---|---|
| 固定长度 | 正整数，例如4 | 读取指定字节数 |
| 读到分隔符 | `&`、`;`、`=`、`\n`等 | 读取分隔符之前的非空内容，并消耗分隔符 |
| 读取到帧尾 | 留空 | 读取剩余内容，只能排在最后 |
| 按命令码识别 | 留空 | 依据已保存映射匹配ASCII命令，保留原行为 |

ASCII分隔符支持`\r`、`\n`、`\t`、`\xNN`和`\\`；HEX分隔符填写十六进制字节。空白分隔符可写成`\x20`以免与表格空值混淆。无效转义、空分隔符、超过128字节或包含完整帧尾的分隔符明确拒绝。固定字段的值必须与实际字节一致，不把分隔符拼进命令码。

例如帧头`@&`、帧尾`\r\n`，以下完整报文：

```text
@&5A&01&SCT&1&0;MFCV=255;10\nEND&?&\r\n
```

对应顺序行：

| 字段 | 作用/类型 | 长度方式与配置 |
|---|---|---|
| 源地址 | 固定字段/ASCII，值5A | 读到`&` |
| 目标地址 | 固定字段/ASCII，值01 | 读到`&` |
| 报文类型 | 固定字段/ASCII，值SCT | 读到`&` |
| 序号 | 普通字段/无符号整数 | 读到`&` |
| 等待标志 | 执行控制/无符号整数 | 读到`;` |
| 命令码 | 命令码/ASCII | 读到`=` |
| 参数 | 参数/无符号整数 | 读到`;` |
| 延时 | 执行控制/无符号整数 | 读到`\n` |
| 固定结束文字 | 固定字段/ASCII，值END& | 固定4字节 |
| 校验值 | 校验值/ASCII | 读到`&` |

同一张表可读取序号1、12、255，以及MFCV、LED、XYZ_PX等不同长度的命令码和单个整数。以上常量只来自配置资料，程序没有客户专用分支。`examples/delimited-single-parameter.json`提供另一套可直接导入的通用单参数配置。

## 解析与发送边界

点击“解析格式”直接使用当前顺序表，不要求映射或设备参数，不生成目标帧。命令码按分隔符读取时，未知命令也可独立展示；转换发送找不到映射则拒绝。零条映射的格式可保存、重启、导入和导出。

只有作用为“参数”的整数行可用于趋盛参数映射。普通字段仅展示；等待、延时等应标为“执行控制（仅解析）”，该字段实际存在时转换发送拒绝，避免静默忽略其含义。校验值只提取并提示“未校验”，没有实现客户校验算法。原有调试发送对软件范围/行程的兼容行为不变；独立格式解析与已保存配置预览仍检查逐行范围。

数字必须是完整十进制整数，不自动去空格，不接受小数、正号、溢出或`20,200,3000`之类多值输入。缺分隔符、空值、固定文字不符和多余数据均明确失败，并清空旧字段/目标帧。程序不取第一个数字冒充单参数，也不执行多命令批次。

完整帧及缓存最多4096字节。全固定长度HEX帧仍按长度定位结束，允许参数字节与帧尾相同；含分隔字段的正文不能出现完整帧尾序列，分隔符本身也不能嵌在字段值中。半包等待、粘包逐帧处理，错误帧不会冒充成功。旧mappedCommand及input.omitFields在变长前缀后继续工作，省略字段仍由明确配置决定。

## 旧两版格式的恢复

模板与样例两版的入口、编辑器、解析模块及示例已移除。含`external.mode=textTemplate`或`external.textFormat`的配置返回`UNSUPPORTED_FORMAT`。

导入这种文件会拒绝，当前草稿和原文件不变。启动恢复本地旧草稿时，不改写文件，只展示其中保留的顺序字段和恢复提示；检查并显式保存前，独立解析、预览及发送均禁止。用户点击“保存配置”后才移除已知废弃键，并把原mode/textFormat保存到根`retiredFormatBackup`，包括其未知扩展。其他根、external、device、字段未知扩展继续保留。旧文件如果没有顺序fields，需要用户重新填写原表，不能从旧模板猜测布局。
