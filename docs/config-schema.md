# Protocol configuration version 1

`schemaVersion` is currently `1`. The JSON file contains `external`, `mappings`, `responses` and `device`. `ProtocolConfig::fromJson` validates and computes a SHA-256 version from normalized JSON. `QSaveFile` writes imports/exports atomically. The UI edits a draft; enabling copies a value snapshot. Each accepted request stores that version and response formatting until it completes.

## External frames

* `ascii`: `template` has a fixed prefix and terminator plus numeric placeholders such as `!MOVE,{position}\r`. Each placeholder must have a field definition. The first stage accepts integer placeholders, with optional `min`, `max`, `constant`.
* `binary`: `headerHex`, optional `footerHex`, and exactly one of `fixedLength` or `lengthField {offset,size,endian,base}`. Fields have `name`, `type` (`uint`, `int`, `ascii`, `constant`), `offset`, `length`, `endian`, and optional range/constant. The length field value plus `base` is the total frame length. Maximum buffered input is 4096 bytes.
* `dt`: a dedicated strict parser for one `/[1-9]A<n>R CR`, `/[1-9]a<n>R CR` or `/[1-9]Q CR`. It rejects any other command, command string, buffered execution or broadcast. `R` is an execute command; `CR` ends the frame.

Optional binary `crc` uses `algorithm` (`crc16-ccitt-false` or `crc16-msb`), `polynomial`, `initial`, `xorOut`, explicit `reflectIn:false`, `reflectOut:false`, `from`, `toExclusive`, `offset`, and `endian`. Reflected variants are not implemented. A CRC value in an external input is checked before mapping. The Qusheng target CRC is generated by the verified-in-code fixed encoder, not copied from the external frame. Hardware CRC agreement remains unconfirmed.

## Mappings and device profile

Mapping entries have an optional `when` equality object, `operation` (`ABSOLUTE_MOVE` or `QUERY_MOTOR`), `responsePolicy` (`ack`, `complete`, `query`) and `parameters` keyed by semantic names. Expressions support `constant`, `field`, `enum` lookup, `linear {field,numerator,denominator,offset,round}` and `bits {parts:[{shift,width,value}]}`. `round` must be `floor`, `ceil`, `nearest` or `exact`. Negative inputs and arithmetic overflow are rejected. No scripts are executed. `ABSOLUTE_MOVE` requires `positionUm`; the device profile supplies `speedUmPerS` and confirmed absolute action direction. All positions are checked against `minPositionUm` and `maxPositionUm` before target encoding.

`device` carries `destination`, `source`, `devId`, `absoluteAction`, `speedUmPerS`, `minPositionUm`, `maxPositionUm` and confirmation flags. Real sending additionally requires `confirmed`, `conversionConfirmed`, `crcConfirmed`. DT real sending also requires `dtErrorMapConfirmed` and a confirmed `defaultDtErrorCode`; `dtErrorCodes` may override individual local error codes. Until error semantics are confirmed the supplied DT example cannot be used live. Non-DT formats require `responses` entries `ack`, `complete`, `reject` (ASCII text or binary hex). Binary response templates in this phase are fixed byte strings; dynamic target templates, response length/CRC derivation and nested variable structures are later work.

## Runtime states

`RequestManager` emits `Queued → Sending → Written → WaitingReply → Acknowledged → InMotion → Succeeded` as applicable. Independent timers bound write, command ACK and motion completion. It never retries a motion. After a 0x11 ACK, uppercase `A` may return a DT busy status while the manager keeps polling 0x12. Lowercase `a` waits for 0x12 idle **and** requested absolute position before returning idle. 0x17 updates busy information but cannot complete a request by itself. A cancelled wait does not stop the device. An 8-bit sequence is never reused within one connection; after 256 frames the encoder fails closed until a new downstream session is established.
