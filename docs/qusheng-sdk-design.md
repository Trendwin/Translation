# 趋盛SDK架构与使用

本轮基于main 741472a，按用户确认先实现单条简单控制和查询。协议原文件仍可读取；无需重传。动作、事件、升级和复杂配置流程暂缓；C1/72保留接口并返回布局待确认。

## 调用分层

客户字段解析 → 参数映射 → SDK补齐与校验 → 载荷编码 → 完整帧 → 单下游请求 → SDK回告解析 → 界面显示。

`src/qusheng/sdk` 是可单独引用的QtCore源码SDK，不依赖客户语法、JSON资源、Widgets或SerialPort。公共接口为 `qushengsdk.h`，构建入口为 `qusheng-sdk.pri`。登记表给出56族接口名称、参数类型/范围、默认来源与能力状态；目录保留名称和协议章节，从SDK取得普通命令能力及参数，而不是另写执行白名单。

- `sdkrequests.cpp`：登记、默认补齐、整数/枚举/通道/保留位/组合关系校验、30族载荷编码。
- `sdkreplies.cpp`：逐命令回告长度、错误头、查询扩展与主动上报解析。
- `sdkframes.cpp`：既有AA AA帧、长度反码和CRC，保持原样例字节。
- `QushengProtocol`：软件适配器，保存地址/序号与接收缓存，调用SDK，不维护另一套业务字节布局。
- `ConversionEngine`：通用字段与参数映射，取得已补齐参数及来源快照，不认识DT。
- `RequestManager`：串行请求、应答超时、完成跟踪。普通命令收到有效应答即结束；既有运动仍跟踪空闲和本次终点。

预览和真实发送使用同一SDK编码；预览使用独立序号会话，最终以实际下发帧为准。坏长度回告显示错误并继续等待，设备明确拒绝回告可以短至四字节且结束请求。08空心跳/09合法模块故障记录优先分流，即使序号碰巧相同也不当作设置回告；17上报不解除新请求的运动占用。普通位置运动受未知占用限制，停止/复位和普通控制/查询可用于恢复。未知占用按电机编号记录，查询另一路空闲不解除前一路的占用。0x11停止可替代同一电机运动等待，须等前一帧写出完成后发送；复位等待空闲及有效位置，不假定逻辑零点数值。0x05仍通过串行请求队列，不自动抢占在途请求；需要时先取消本地等待再发送该指令，随后查询实际空闲状态。

## 当前已实现的30族

| 分组 | CMD |
|---|---|
| 设备与通信 | 01、03、04、05、08、09、0C |
| 步进控制与查询 | 11、12、14、16、1A |
| 电磁阀 | 21、22、23、24、25 |
| 模数/数模 | 44、46、54 |
| 电源 | 63、64、65 |
| 风扇 | 81、82、83、84 |
| 数字/直流 | 91、92、A1 |

SDK提供0x11四动作及协议模式编码；软件新建映射固定绝对模式4，四动作均已接入发送。前进/后退保留终点跟踪；停止/复位固定零距离，各自使用停止/回零状态判断。旧相对配置仍兼容。0x05是独立的协议紧急停止接口，普通应答并不替代电机空闲状态查询。

完整56族中的4个仅接收接口为17/45/D9/E6；本轮解析08/09/17/45主动上报，D9/E6保留原始字节，动作/事件处理以后扩展。0B、13、15、71、73、74、C2、C3及动作D/事件E接口保留但暂缓编码；C1和72明确返回布局待确认。尚未实现的目录条目不能通过JSON状态或原始负载绕过许可。

## 默认参数

优先级为明确映射值 → `sdkDefaults`用户预置 → 设备参数 → SDK软件初始值。完整请求保存补齐后的参数及来源，不在发送时再次读取可变草稿。

普通用户可在现有参数表选择“默认值”、客户字段或固定值；固定值即可覆盖默认值。高级JSON可按操作保存重复使用的SDK预置，例如：

```json
"sdkDefaults": {
  "QUSHENG_81": {"devId": 225},
  "QUSHENG_22": {"devId": 50}
}
```

| 默认项 | 软件初始值或来源 |
|---|---|
| 步进编号、速度 | 设备参数，独立SDK无设备上下文时为0x11、1000 |
| 阀、ADC、DAC、风扇、直流编号 | 0x31、0x61、0x71、0xE0、0x21；不会误用步进编号 |
| 电源模块 | 0xC5 |
| 心跳间隔、ADC上报间隔 | 0，关闭上报 |
| 错误上报开关 | 1 |
| 阀持续时间/超时 | 0，按协议采用超时配置或常开行为 |
| 风扇百分比、DAC数值、直流PWM | 0 |
| 电源开关 | 0，关闭 |
| 电源上电延时 | 0，即立即开启；不是出厂默认不开启状态 |
| 风扇每转脉冲/滤波/测速间隔 | 1、1、1000；阈值0/255 |

以上软件初始值不宣称都是厂家默认值。板地址/DevID、各通道、延时、阀常开和输出范围仍需实际设备核对。0x01功能掩码会改变板卡功能，必须明确提供；0x11前进/后退目标位置同样必须提供。协议固定数据04/23=00 00及预留位由编码器写入，禁止映射覆盖。

SDK预置在配置校验时检查类型、通道、保留位及组合关系。四种运动模板只预置编号和速度，不能覆盖固定模式/动作；前进/后退目标位置通过映射提供，停止/复位距离固定0。客户声明字段仍由通用解析器完整读取，SDK缺省参数不等于自动省略客户字段。

## C++引用

qmake工程加入 `QT += core`、`CONFIG += c++11` 和 `include(.../src/qusheng/sdk/qusheng-sdk.pri)`：

```cpp
QushengSdkRequest request;
TranslationError error;
QVariantMap supplied{{"percent", 50}};
QVariantMap preset{{"devId", 0xE1}};
if (QushengSdk::buildRequest(0x81, supplied, preset, {}, &request, &error)) {
    QByteArray frame = QushengSdk::makeFrame(2, 1, 0, request.command, request.payload);
    // frame交给调用者的传输层；SDK不自行写串口、不分配会话序号。
}
```

应答载荷调用 `decodeReply`，主动上报载荷调用 `decodeReport`。`success=false`且解析返回true表示设备拒绝；返回false表示布局/长度/支持能力等解析失败。原始负载一直保留。

## 验证示例及协议差异

导入 `examples/sdk-simple-controls.json`，可预览 `/1FAN50R\r`、`/1VAL1000R\r`、`/1DAC1000R\r`、`/1DC-30R\r`、`/1ADCR\r`、`/1DIR\r`、`/1STATR\r`。客户字符和格式均仅在配置中，SDK不识别这些客户命令。

协议差异按实际表格留痕：21应答采用2字节错误码+2字节状态；84设置回告的六字节扩展保留原样，不伪造82完整配置；92按V0.1.7的24路三字节输入解码；1A只接受11～13；15查询解码有符号int32。C1阀泵速度/距离D6重叠及72索引/数据重叠未猜测。

08/09上报序号语义、21特殊头、84扩展、模块通道和参数物理尺度须以真实收发记录进一步核对。组帧成功表示字节按当前文档生成，不表示设备已执行或复杂升级流程已完成。

## 测试入口

`tests/tests.pro`、`tests/ui-tests.pro`保留软件回归；`tests/sdk-requests.pro`和`tests/sdk-replies.pro`为独立QtCore测试。逐族使用独立预期载荷/回告，不用SDK自编自解代替协议验证；包括默认值优先级、非法参数、保留位、有符号负值、24/32位边界、短错误、上报隔离和255字节上限。实际双环境结果见phase1.md。
