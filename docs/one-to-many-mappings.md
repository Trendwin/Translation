# 一条客户命令对应多条趋盛指令

原九列顺序字段表和直接参数下拉保持不变。同一客户命令可以配置1～64条有序趋盛指令，每条独立选择指令、电机、参数来源或固定值，也可重复同一种指令。输入格式、参数项数与省略字段由整组共用，不按各步目标参数数量猜测输入。

## 编辑新组

1. 在“添加新映射”填写客户命令，按当前方式选择第一条趋盛指令及参数。只有一条时仍可直接点击“添加命令映射”。
2. 多条时点击“添加/更新本条指令”，让本条进入清单，再点击“新增下一条”。逐条设置，来源直接选“第N个参数”或固定值。
3. 在清单中选择某条可修改这个新组中的该条；用上移、下移、删除调整顺序。切换时会校验保存有效编辑，非法内容会保留并提示；可点“放弃本条修改”恢复该条已入清单的值。
4. “整组共用输入”明确选择是否读取客户参数。已有参数步骤后加入停止或查询，不会自动省略其它步骤要用的参数。若先加入无参数查询，随后需要参数运动，请把整组改为读取客户参数并设置项数。
5. 最后点击“添加命令映射”，把整个新组加入上方已有映射，再保存配置。当前未入清单的有效编辑会一并校验纳入，非法编辑阻止添加。上方已有映射仍通过显式删除后重建，不因选择或编辑下方内容被覆盖。

## 执行与结果

收到客户报文后先解析一次，校验整组并求出所有指令的数值、设备地址和默认参数快照。任何一步静态错误都会清空本次预览及发送列表，整组零发送。离线预览按顺序展示每条操作、目标、参数换算与目标帧；实际发送仍以真实会话序号和CRC为准。

整组按配置顺序发送。只有前一条完整写出且收到匹配成功应答后才继续；普通后续组不会插入组内。任一步拒绝、超时、写失败、断连或取消都停止剩余步骤，不自动重发，不回滚已经发出的动作。结果显示已接纳数量、失败步骤和剩余未发送数量。

**成功ACK只表示设备接纳，不表示机械动作完成。** 不自动轮询完成，也不增加延时、等待条件或动作回滚。旧相对运动的当前位置前置查询保留，执行到那一步时仍可能因设备状态或终点校验失败；先前已发步骤不能撤回。

“取消本组”取消最近提交组的本地等待和剩余发送，不向设备发送停止命令。需要物理停止时单独提交停止映射。组内的停止指令按原顺序执行；外部单独停止保留优先处理，并取消涉及同一物理电机的组剩余，虚拟模块与其它电机不混同。

应答可早于本地写出完成，软件仍等待当前写操作释放后才发下一帧。写超时而底层仍未结束时会明确提示等待写出结束、必要时断开串口恢复，不抢写、不重复运动。

执行控制字段仍仅解析并禁止下发；校验值仍只提取，未验证客户校验算法。批量步骤不绕过六路物理电机范围、SDK参数检查或输入列表数量约束。

## JSON与示例

`examples/one-to-many-mappings.json`是通用演示，不声明客户校准命令的实际硬件用途：

- `!TRIPLE=20,30,40\r`：电机前进取第1个参数、XYZ三个位置分别取1/2/3、再重复第一条电机前进。
- `!SEQUENCE=20,30,40\r`：同一电机依次前进、停止、后退；停止不会把组内其它步骤重排或删除。
- `!ONE=50\r`：保留旧一对一表示方式。

schemaVersion仍为1。客户命令码唯一，根input共享。旧operation/parameters继续有效；新组使用steps，不能与根operation/parameters混用，也不能在step中设置input、commandCode或嵌套steps：

```json
{
  "commandCode": "PAIR",
  "input": {"parameterCounts": {"values": 3}},
  "steps": [
    {"operation": "MOTOR_FORWARD", "parameters": {"positionUm": {"kind": "field", "field": "values", "itemIndex": 2}}},
    {"operation": "MOTOR_STOP", "parameters": {}}
  ]
}
```

步骤可保留field/linear、列表索引和高级分数/偏移/舍入关系；未知扩展在根、映射、步骤和表达式各层随保存保留。字段改名会遍历组内所有步骤同步引用，删除或改类型会指出失效步骤，不自动改绑。已排队组使用接收时快照，之后修改配置、默认参数或地址不会影响该组。

开发入口：`convertBatch`输出有序`ConversionPreview.steps`，每项含command、parameterTrace和targetFrame；旧`convert`遇多条明确返回MULTI_STEP_REQUIRES_BATCH，不能悄悄只取第一条。服务通过submitUnifiedGroup一次入队；groupProgress报告组进度，groupCompleted每组只报告一次最终结果。
