# 协议字段与命令映射联动

客户协议格式是参数映射的前提。用户在字段表中把同一字段由“位置”改为“数据参数”时，所有运动映射的来源和查询映射的省略字段随之更新，不需要逐条重选。

## 自动跟随的范围

- 同一字段行改名：同步全部映射的field/linear来源及input.omitFields，包括未选中的映射和待实现指令的多个参数。
- 换算分子分母、偏移、取整、固定值和扩展元数据保持不变；当前映射的未保存编辑先保留，再处理字段联动。
- 新增、删除、排序、作用和数据类型变化后，来源列表与省略选项跟随当前字段表刷新。

字段名称编辑中的空值或重复值是暂态，不能立即按文本逐项替换。界面保留同一字段行上次同步的名称，等全表名称合法且唯一后，用一次旧名到新名的对应关系同步；交换两字段名也不能串绑。重新加载整份JSON时重置这一编辑身份，不按行号或类型猜测改名。

## 需要修正的变化

删除仍被引用的字段、将来源改为ASCII或固定字段、以及引用已省略字段时，保留失效关系并明确显示受影响的客户命令和来源。不得自动选择另一个数值字段，也不得把失效引用变成固定零。格式和映射可逐步编辑；配置校验通过之前不能启用或生成目标帧。

JSON整体替换没有可确认的同一行编辑身份，需要同时修改fields和映射引用；配置校验会指出不一致处。首版不增加面向用户的字段ID或新的配置设计器。

## 草稿与运行版本

字段联动只改变正在编辑的表单。保存到草稿之后再校验、启用，已启用快照及在途请求保持原样。保存失败不能把编辑标成成功，也不能推进未同步的名称基线。

## 验证重点

“位置→数据参数”后，运动与查询均按同一配置预览，保存再载入结果一致；高级关系和多个参数保真。另检查连续改名、改回、临时空名/重名、字段顺序、删除/类型变化、当前未保存映射，以及草稿与已启用版本隔离。
