# 格式表与未使用参数

普通顺序格式始终按照格式表完整读取报文。映射是否需要某个值，不应改变线上字段顺序。例如命令读到`=`、整数列表读到`;`、延时读到`\n`，报文中的`RESET=0;10\n`会解析为参数`[0]`、延时`10`。即使RESET只映射复位动作、不使用这个参数，软件仍读取并校验参数0，不会让延时误读成`0;10`。

“解析格式”不依赖映射、目标指令或设备配置；删除映射、修改目标、选择“不使用客户参数”均不改变普通格式的解析结果。转换和串口分帧使用同一字段布局。空值、坏整数、范围超限、缺失分隔符仍报错，未使用不能绕过格式校验。

现有`input.omitFields`原样保留。在普通格式中，它表示本映射不使用指定字段，因此不能再用表达式引用这些字段；未使用的整数列表无需额外设置输入项数。若对线上仍存在的列表明确配置`parameterCounts`，转换仍检查实际数量完全相同。可用列表和field/linear引用仍需正确数量及itemIndex。无需重建旧RST映射。

仅命令字段选择`mappedCommand`（按命令码识别）时，保留旧短报文兼容：omitFields实际从旧布局省略指定字段，例如`/1ZR\r`、`!RST\r`。变长分隔前缀加mappedCommand仍按原规则工作。软件不会尝试完整布局失败后再猜省略布局。普通分隔格式的`Q=`不能省掉后续参数字段，需要按格式提供值，如`Q=0`。

通用示例[format-driven-unused-parameter.json](../examples/format-driven-unused-parameter.json)可直接导入，解析：

```text
[AA|BB|CTL|1|0;RESET=0;10\nDONE|?|]\r
```

结果保留数值`[0]`、延时`10`、等待标志和校验值。RESET示范三条独立电机复位映射，客户参数不参与目标取值。示例的等待和延时明确为执行控制，**本轮仅解析，禁止转换发送**；校验值仅提取、未验证。不要把实际有执行含义的字段改成普通元数据来绕过保护。这里不实现等待或延迟动作。
