# 上游虚拟串口

Translation 提供一个供上游软件连接的 COM 口。内部使用一对 com0com 虚拟串口：界面只显示上游应该选择的一端，另一端由 Translation 自动打开接收。

## 第一次使用

1. 将程序放在可写目录，打开“报文调试 → 上游虚拟串口”。
2. 点击“初始化虚拟串口”，确认 Windows 管理员授权。软件会检查已安装的 com0com；没有时安装随程序附带的签名驱动，再创建自己的端口对。
3. 等待界面显示提供的 COM 口，例如 `COM10`。具体号码根据电脑上空闲端口自动分配。
4. 在上游软件选择这个 COM 口，设置 **115200、8 数据位、无校验、1 停止位、无流控**，然后打开连接。
5. 上游发送数据后，“原始接收”显示串口接收块的 ASCII 和 HEX。左侧保留最近 100 条有效帧，点击一行可看该帧的解析字段、转发结果或原始字节。完整报文按 Translation 中已经保存的客户格式拆帧、解析。

例如保存极瞳的顺序字段格式后，上游按 ASCII 原样发送下列内容（其中 `\n` 是两个字符，`\r\n` 是四个字符，均不解释成控制字符）：

```text
@&5A&01&SCT&1&0;PX=10;10\nEND&?&\r\n
```

接收页应显示命令 `PX` 和参数 `10`。关闭串口助手的转义处理和自动追加回车换行。手动调试中的同一段文字采用相同规则。等待标志、执行延迟等字段的解释仍由保存的格式决定；当前不执行等待时设为普通字段。JSON写法及字节对照见[ASCII文本](ascii-text.md)。

## 后续启动

再次打开同一目录的 Translation 时，会自动检查已有专用端口并开始接收，无需重复安装。上游软件继续选择界面显示的同一个 COM 口。关闭 Translation 会释放内部接收端，Windows 中的虚拟端口对会保留。

## 自动转换下发

在“设备与连接”中连接下游控制板串口后，无需再点发送：上游发来的完整有效报文会按**已保存配置**转换为趋盛指令，进入下游发送队列。上游报文保持原样，不将客户 ASCII 报文直接透传给控制板。

例如导入并保存 [ASCII 原样顺序格式示例](../examples/literal-ascii-sequential.json)，上游发送 `@&5A&01&SCT&1&0;MFCV=255;10\nEND&?&\r\n`，会按该示例映射生成两条有序阀控制指令。先验证整组并保存快照，前条完整写出且收到成功应答后再发下一条；失败、超时或断连停止本组余下指令。**已入队、已写出、设备已应答是不同状态，成功应答不代表机械动作完成。** 连续上游报文与手动发送共用现有队列，避免串口写出的字节交织。

- 上游接收、转换与转发、下游应答分别显示。下游未连接时，有效帧仍计入接收记录，该帧显示“未转发”，且不增加错误数。断开期间的报文不会入队，重新连接后只处理新收到的报文。具体原因可在“接收与转发日志”查看。
- 格式错误、未知命令、映射或参数错误均显示具体原因，不发送旧预览结果。自动转换遵守保存的字段范围、列表项数、公式与设备行程，不使用手动调试放宽范围的临时配置。
- 正在编辑但未保存的内容不会改变自动转换；保存或导入后，新报文采用新配置，已经入队的组保持原快照。
- 自动来源最多保留128个待处理客户报文组；队列满时明确拒绝新报文并提示，不静默丢失或自动重试。
- 软件仍不回复上游。上游页显示本机接收与下游执行状态，不会把下游回告自动回写给上游软件。

上游没有打开或没有发送数据时，软件显示等待报文；内部虚拟端口已打开并不代表上游软件已连接。手动报文调试功能保持原有操作方式。

## 配置与异常

- 专用端口记录保存在程序旁的 `config/upstream-port.json`，初始化日志为 `config/upstream-setup.log`。端口记录与协议配置分开，导入客户 JSON 不会改变它。
- 请保留端口记录，不要为了重试而删除。程序只恢复有记录且标识匹配的专用端口，不会接管、改名或删除电脑上已有的其他端口对。
- 将整个目录复制到另一台电脑后，需要在新电脑初始化其本机端口。
- 如端口被另一个 Translation 实例占用，请先关闭那个实例，再点击重试。
- 取消管理员授权后可以重新初始化。若驱动或端口尚未就绪，按照界面提示重启 Windows 后重试；仍失败时请保留端口记录和日志供维护人员检查。
- 附带驱动支持 x86/x64 Windows。能否加载由目标电脑的 Windows 驱动策略决定；软件不会修改系统签名、安全启动等安全设置。第三方驱动来源、许可证和对应源码见 `third_party/com0com`。
