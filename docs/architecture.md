# 架构说明

## 数据流

软件输入框 → ConversionEngine → UnifiedCommand → RequestManager → QushengProtocol → 下游串口

设备回告由下游串口进入QushengProtocol和RequestManager，界面显示原始字节、解析结果和请求状态。运行时只有一个SerialTransport，没有客户侧串口或客户回写接口。

## 职责

- ProtocolConfig校验schemaVersion JSON，生成SHA-256版本；inputFormat按配置省略字段和覆盖帧尾，不按客户协议名称选择布局。
- ConversionEngine只依赖保存的帧边界、字段表和命令映射，完成通用分帧、字段解析、最长配置命令码匹配及参数换算。
- UnifiedCommand/UnifiedResult传目标操作、设备、数值、单位约定、响应策略和诊断数据，不携带客户设备内置语法。
- QushengProtocol仅支持受限的单条绝对/相对运动、0x12电机查询和0x04设备版本查询，保留地址、序号、长度反码和既有CRC校验。
- QushengCommandCatalog从随程序发布的中文目录加载全部56类目标指令，将0x11展开为四种固定绝对模式动作，共59个新建选项。旧模板单独供既有配置兼容，不加入新建池。执行许可来自编译后的白名单，不能通过JSON中的状态或备注改变。
- RequestManager串行发送请求，分别管理写出、应答和完成，不自动重发运动。
- Widget用四列映射摘要和选中编辑表单替代复杂横向表格，保留草稿/校验/启用/确认边界。

## 配置和界面状态

编辑控件、行级映射JSON、已保存草稿、已校验草稿和已启用快照不能合并。列表切换先把编辑写到行数据，“保存到草稿”才更新JSON草稿。打开简化表单不能把精确分数变成舍入后小数，修改命令码或反馈时机不能丢失高级关系、独立帧尾或元数据。

目录选择与运行支持也不能合并。待实现的下发指令可以保存草稿参数，并与已支持映射共存；转换命中待实现映射时明确拒绝，目标帧为空，不能误落入绝对运动分支。设备主动上报项标“仅接收”，配置层拒绝下发映射。搜索只改变可见选项，不能自动改写当前操作。

简洁界面删除教学说明、目录浏览/分类、偏移/取整及离线回告解析控件，日志移至调试页签。既有表达式和命令输入格式仍来自行数据JSON；删除控件不能导致保存时重置偏移、取整、独立帧尾或省略字段。详细设计见expert-ui.md。

新MOTOR_FORWARD/BACKWARD的模式固定4、动作固定1/3，唯一客户参数为positionUm；速度、电机编号来自设备默认配置。配置转换与编码器均从操作决定动作，忽略旧设备方向及注入的动作参数，不能把新运动伪造成停止/复位。MOTOR_STOP/RESET只保存草稿，直接调用编码器也会拒绝并清空旧帧。默认速度随每条0x11发送，不建立跨报文速度缓存。

每个请求复制启用参数并记录版本。在途请求不受后续编辑影响，执行期间禁止切换运行版本。字段删除或改名后保留失效引用，不能自动改成另一个字段。任何输入或配置失败均清空预览目标帧，不能显示上一条合法帧冒充本次结果。

## 请求状态

0x11成功回告只代表接纳。ack策略可以先反馈一次接纳结果，但设备仍忙、请求仍占用队列；完成轮询0x12确认空闲且位置等于本次目标后才释放。complete策略到该时刻才反馈成功。接纳后若超时或失败，独立错误信号仍显示最终原因。

相对运动多一个前置查询阶段。前置0x12确认当前位置已知、已回零且空闲，计算当前位置±距离，并核对行程，再发送一次0x11。前置查询不能当成动作完成查询：前置失败意味着没有发送运动；运动发出后查询失败意味着设备可能已经运动，保持忙或状态未知。取消本地等待不等于设备停止。

只读查询有独立完成分支，不能落入运动轮询。0x04展示版本和设备标识，不更新电机忙闲；0x12可确认忙闲。主动0x17或迟到回告不能直接完成新请求；地址、命令、序号和长度必须匹配。

## 本轮范围

当前提供单条绝对/相对运动与只读查询。客户代码和大小写对应均由示例JSON描述；通用解析器没有DT、A/a、P/p、D/d等专用判断。新示例直接使用数值，客户与设备物理单位的等价关系另行确认。

ITransport、IInternalProtocol、配置表达式和受限目标模板保留扩展边界。本轮不实现位拼接、脚本、动作集、复合指令、循环、TCP或通用CRC编辑。旧未编译的客户回包演示残留已清理；下游演示编码器仅供既有测试回归。

同一物理连接的8位序号不回绕，耗尽须重连；启用配置不重置序号。预览使用独立编码器，真实序号由请求管理器分配，实际发送帧才是线上依据。
