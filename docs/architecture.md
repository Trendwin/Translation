# 架构说明

## 数据流

软件输入框 → ConversionEngine → UnifiedCommand → RequestManager → QushengProtocol/SDK → 下游串口

设备回告由下游串口进入QushengProtocol和RequestManager，界面显示原始字节、解析结果和请求状态。运行时只有一个SerialTransport，没有客户侧串口或客户回写接口。

## 职责

- ProtocolConfig校验schemaVersion JSON，生成SHA-256版本；inputFormat按配置省略字段，帧尾只来自共用格式，不按客户协议名称选择布局。
- ConversionEngine只依赖保存的帧边界、字段表和命令映射，完成通用分帧、字段解析、最长配置命令码匹配及参数换算。
- UnifiedCommand/UnifiedResult传目标操作、设备、数值、单位约定、响应策略和诊断数据，不携带客户设备内置语法。
- QushengSdk是独立QtCore模块，登记56族、实现30族简单请求/回告及08/09/17/45上报；QushengProtocol只适配业务请求和序号缓存，帧与载荷布局调用SDK。SDK参数定义/默认值/能力为普通指令单一来源，详见qusheng-sdk-design.md。
- QushengCommandCatalog从随程序发布的中文目录加载全部56类目标指令，将0x11展开为四种固定绝对模式动作，共59个新建选项。旧模板单独供既有配置兼容，不加入新建池。执行许可来自编译后的SDK能力及少量既有运动发送限制，不能通过JSON中的状态或备注改变。
- RequestManager串行发送请求，分别管理写出、应答和完成，不自动重发运动。
- Widget用三列映射摘要和选中编辑表单替代复杂横向表格，保留草稿/校验/启用/确认边界。

## 配置和界面状态

格式/设备编辑控件、表格映射JSON、已保存草稿、已校验草稿和已启用快照保持分离。映射表只读，选择行仅用于删除，不加载到下方表单，也不存在把表单写回选中行的入口。新表单只有点击“添加命令映射”才会生成新JSON追加到表格；保存草稿与发送只读取已添加的表格行，不隐式提交尚未添加的内容。高级映射元数据保留在行JSON中，不经新增表单重建。

目录选择与运行支持也不能合并。待实现的下发指令可以保存草稿参数，并与已支持映射共存；转换命中待实现映射时明确拒绝，目标帧为空，不能误落入绝对运动分支。设备主动上报项标“仅接收”，配置层拒绝下发映射。搜索只改变可见选项，不能自动改写当前操作。

简洁界面删除教学说明、目录浏览/分类、偏移/取整及离线回告解析控件，日志移至调试页签。既有表达式和命令输入格式仍来自行数据JSON；删除高级计算控件不能导致保存时重置偏移、取整或省略字段。反馈时机和独立帧尾已按用户新要求移除：界面载入清除旧两项，帧尾只来自external。详细设计见expert-ui.md。

新MOTOR_FORWARD/BACKWARD的模式固定4、动作固定1/3，唯一客户参数为positionUm；速度、电机编号来自设备配置或SDK预置。MOTOR_STOP/RESET已接入发送，模式4、动作2/4、距离0固定，旧草稿距离关系不求值。配置转换和编码器均从操作决定固定值，不能通过注入参数改成其他动作。默认速度随每条0x11发送，不建立跨报文速度缓存。

每个请求复制启用参数并记录版本。在途请求不受后续编辑影响，执行期间禁止切换运行版本。同一字段行改名时，以一次名称对应关系同步所有参数引用和省略字段；删除或类型变化不能猜测替代来源。名称编辑暂态与已同步身份分开保存，整体JSON替换重新建立基线。详见[field-adaptation.md](field-adaptation.md)。任何输入或配置失败均清空预览目标帧，不能显示上一条合法帧冒充本次结果。

## 草稿持久化

草稿持久化由独立QtCore组件DraftStore负责，保存原始JSON对象而不调用运行配置校验；ProtocolConfig继续负责运行格式校验和有效配置导出。窗口保存成功后才更新内存草稿和“已保存”状态，启动时优先读取用户目录草稿；main固定应用标识使重新编译或更换启动目录不影响存储位置。读取失败不覆盖原文件，恢复草稿不自动启用或连接设备。

## 请求状态

0x11成功回告只代表接纳。有效回告经replyReceived立即显示，前进/后退/停止/复位收到应答后结束本地等待，不宣告机械动作完成。RequestManager只保留写出和应答超时，不再持有轮询或动作完成定时器。设备忙闲仅作显示，不作为界面或底层的发送条件。界面允许等待应答时继续点击发送，普通请求按队列逐条写出；有效应答及完整写出后才放行下一条，发送前不要求手动查询。

同一电机停止优先进入队首，替代原运动等待并取消同一电机排队运动。m_writePending跟踪真实写出，m_sendAfterProbe保存早到前置查询的待发送运动，m_finishAfterWrite保存早到完成回告后的串口释放等待；三个状态不能合并成“已收到回告”。界面请求占用从RequestManager读取，通过activityChanged更新，取消排队停止不会误释放原运动。

相对运动多一个前置查询阶段。前置0x12确认当前位置已知、已回零且空闲，计算当前位置±距离，并核对行程，再发送一次0x11。前置失败意味着没有发送运动；发送运动并收到应答后不再自动查询。用户手动查询失败时保持忙或状态未知。取消本地等待不等于设备停止。

只读查询收到有效回告后结束，不衍生下一次查询。0x04展示版本和设备标识，不更新电机忙闲；0x12可确认忙闲。主动0x17或迟到回告不能直接完成新请求；地址、命令、序号和长度必须匹配。

## 本轮范围

当前提供SDK30族简单控制/查询，动作事件及复杂流程暂缓。客户代码和大小写对应均由示例JSON描述；通用解析器没有DT、A/a、P/p、D/d等专用判断。新示例直接使用数值，客户与设备物理单位的等价关系另行确认。

ITransport、IInternalProtocol、配置表达式和受限目标模板保留扩展边界。本轮不实现位拼接、脚本、动作集、复合指令、循环、TCP或通用CRC编辑。旧未编译的客户回包演示残留已清理；下游演示编码器仅供既有测试回归。

同一物理连接的8位序号不回绕，耗尽须重连；启用配置不重置序号。预览使用独立编码器，真实序号由请求管理器分配，实际发送帧才是线上依据。
