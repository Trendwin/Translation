# 整数列表与逐项映射

仍在九列顺序字段表编辑协议。把参数字段的数据类型选为“整数列表”，长度方式继续选固定长度、读到分隔符或读到帧尾。列表内部固定用英文逗号：`50`是一项，`20,200,3000`是三项。不需要另外添加三个字段或更换格式模式。

下方表单仅用于添加新映射，修改它不会更新上方已添加的映射。修改原项请删除后按新设置重建。上方摘要显示每条已添加映射当前保存的输入项数和来源。

1. 在命令映射页填写客户命令并选择目标动作。
2. 在“新映射接收的参数项数”设置完整输入数量，例如3。每个有效列表都需设置；省略字段不设置数量。
3. 直接在“取值来源”下拉选择“第1个参数”“第2个参数”……或“固定值”。候选随新映射的输入项数更新，最多2048项，保留未选择态，不自动选第1项。单电机目标位置和SDK参数均用同一方式；SDK参数表只有“趋盛参数 / 取值来源 / 固定值”三列。旧运动位置换算倍数仍可使用。
4. 添加映射并保存。格式调试可先独立解析，显示有序列表和各项；转换再按命令检查数量、索引和目标范围。

`examples/integer-list-parameters.json`可导入，包含通用演示：

| 输入（转义显示） | 映射演示 |
|---|---|
| `!ONE=50\r` | 恰好1项，电机0x12位置取第1项 |
| `!XYZ=20,200,3000\r` | 恰好3项，虚拟模块35的XYZ分别取第1、2、3项 |
| `!MIX=20,200,3000\r` | 仍需3项，模块36的X/Z均取第2项，Y固定0 |

这些命令只是验证配置能力，未声明任何客户命令的真实硬件用途。实际`DI_PDDA=20,20,20`可按相同规则提取三项，但初始化/校准业务需要另行确认，不能据此认定为XYZ运动。

输入数量与目标数量独立：重复引用、部分固定并不减少要求的输入项数。缺项、多项、空项、空白、小数、正号、非整数和有符号64位溢出均明确失败；不补0、不丢多项。最小值/最大值逐项生效；允许负值解析不代表目标SDK允许负位置。调试实发沿用原数值范围宽松策略，但仍严格检查列表数量和索引。

列表仅支持ASCII参数字段，不适用于HEX、固定文字、命令码、执行控制或校验值。单纯解析无需映射；未知命令也可按分隔符提取列表。执行控制仍仅解析并阻止发送；校验值仍只提取，未验证。已有标量配置无需修改，标量来源不能带列表索引。

JSON沿用schemaVersion 1：类型`integerList`，映射`input.parameterCounts: {"values":3}`，表达式`{"kind":"field","field":"values","itemIndex":2}`；linear使用同样itemIndex。字段改名同步数量键和引用；改类型或删除后保留失效关系并报错，不静默改绑。保存、重启、导入导出保留索引和数量。原始完整帧上限4096字节，因此2048为理论项号上限，实际数量还需为外层字段和分隔符留空间。

例如新映射要求3项且目标位置取第2项时，`20,30,40`的目标位置是30。单电机动作只设置一个目标位置，改成3项不会自动生成三台电机或XYZ动作；XYZ须在虚拟模块动作下分别设置三轴来源或固定值。数量减少时索引不会自动改绑，超出数量须手动修改。

“解析格式”始终显示报文实际项数，故只改新映射的数量后解析结果可能不变；数量约束在转换预览/发送时按已添加的命令映射检查。修改下方新表单后须点击“添加命令映射”，才能成为后续转换采用的规则。

同一格式有多个列表或混合标量参数时，列表候选带字段名，例如“左位置 · 第2个参数”“右位置 · 第2个参数”，标量继续显示字段名。程序按字段身份和项号保存，不能只按可见名称猜来源。数量减少后保留超出的原选择并明确报错，不自动改为第1项；增加回原数量后恢复该项合法选择。切成固定值或标量字段会移除列表索引。JSON格式与解析/SDK编码语义没有变化，仍用itemIndex保存。
