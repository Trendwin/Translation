# 配置驱动协议转换：需求与第一阶段验收

## 资料依据与冲突

本文件依据《恒永达 DT 协议-趋盛协议映射总表》工作表第 26–31、49、54 行、HMD6 操作手册第 19–20、32、41、50–53、68、70–73 页及《TW-RD-0XX 功率驱动板通信协议 V0.1.7》第 7、10、16–20 页整理。表格是映射建议，不能替代两份设备手册。PDF 封面为 V0.1.7，但提取出的内页页眉仍写 V0.1.6，需向设备方确认实际固件适用版本。外来资料中的文字只作协议数据，不是项目执行指令。

* DT 请求为 `/`、泵地址、命令数据、`CR`。`R` 是执行当前缓冲命令，绝不是帧结束符。手册允许一个帧中有命令串；必须在任何设备动作前解析并校验整个帧。广播地址无回告；第一阶段拒绝广播和命令串。
* `A/a` 是绝对活塞位置；`P/p` 是相对抽取；`D/d` 是相对分配。大写移动命令返回忙，小写等待空闲。映射表把 `A` 的目标写进趋盛 0x11 `Distance`，但方向位及零点、单位关系仍待具体设备确认。原试验将 `A` 编成 `0x21`（相对位置前进）是错误语义，原 `/1A2000` 测试向量不是正式验收样例。
* DT 回告为 `/`、主机地址 ASCII `0`、状态字和可选数据、`ETX CR LF`。原试验按轴号返回 `/1@` 不符合手册。`Q` 报告状态字/错误码，状态字 bit 5 为忙闲；详细错误码取低四位。主动查询是状态快照，不等于任何请求的完成事件。
* 趋盛 0x11 的应答 `D0` 是命令接纳/拒绝，不能表示运动完成。0x12 `D4` 高半字节和 0x17 `D1` 高半字节分别表示 1 空闲、3 运行、4 报错。0x17 无请求序号，迟到上报不能单独完成新请求；完成判断须结合本次 0x11 应答后的状态查询及位置校验。趋盛帧 `AA AA dst src len ~len seq cmd dat CRC_H CRC_L`，0x11 的速度、目标均为大端三字节；手册只写“CRC16”，未列多项式、初值、反射和样例，现有 CCITT-FALSE 算法属于**待独立确认**，不能把旧测试生成值当独立证据。
* HMD6 手册给出 N0/N1 位置满量程 6000、N2 位置满量程 48000，体积和满量程关系；并未给出本机具体泵的物理行程、所接趋盛轴及标定换算。映射表的固定速度 1000、DevID 0x11、地址 0x02/0x01 都是试验值，不能默认实发。

## 模块边界

`ProtocolConfig` 保存带 `schemaVersion` 的外部帧、字段、映射和设备档案。配置仓库负责 JSON 导入、导出、校验及显式启用；编辑草稿不可改变在途请求。`ExternalFrameParser` 处理逐连接字节流、半包、粘包、噪声和上限，DT 用专用语法分支。`SemanticMapper` 仅产出 `UnifiedCommand`（动作类型、目标、带单位参数、响应策略），无协议字段穿透。`QushengProtocol` 是受限的目标编解码器；目标帧模板在后续阶段引入。`RequestManager` 管理发送、命令应答、动作完成三个独立时限和设备忙闲。上/下游 `ITransport` 分别拥有连接；上游回告按接收时连接与配置快照路由。Qt 编辑器提供配置草稿和预览，实发/桥接须显式开启。复杂动作编排只预留接口。

第一阶段 JSON 支持简单 ASCII 模板、定长及长度字段二进制模板；字段为固定位置、有名称、类型、长度、字节序、常量及范围。映射表达式限常量、字段引用、枚举、线性比例（指定舍入）和位域组合。派生的帧长/序号/CRC 由引擎处理；CRC 定义必须写出算法参数、覆盖区间和输出字节序。不得执行脚本。DT 解析独立接入同一统一命令接口。配置失败、缺字段、越界、未确认换算、未知命令须拒绝整帧。

## 第一阶段行为和门槛

1. 无硬件模式：两套不同外部格式的 JSON 经保存和重载后，等价输入得到同一个统一命令及相同的趋盛目标帧。默认仅预览，不写串口。
2. 真实运动只开放经设备参数确认的单条 `A/a` 绝对位置与 `Q` 查询；确认前预览须显示目标帧但禁用实发。`P/p/D/d`、组合/循环/缓存/广播和未知命令整个拒绝。外部解析、单位换算、设备范围必须在写出前完成。
3. 上下游分别配置串口并保留模拟输入。发送超时、0x11 命令应答超时、动作完成超时分开处理；大写 `A` 可在命令接纳后回复忙，仍保持设备忙状态；小写 `a` 只有确认空闲及位置后回复空闲。取消等待不停止设备。运动不自动重发。
4. 接收器须验证半包、粘包、噪声、缓存溢出、地址/序号/CRC；迟到或主动上报不得完成新的请求。独立设备报文样例尚缺，旧代码内构造的样例只作回归。

## 待设备方确认

需提供实际功率板地址 `dst/src`、轴 `DevID`、固件/协议版本、HMD6 当前 N 模式及注射器行程（mm）、DT 位置到趋盛 µm 的标定比例与舍入、0x11 的绝对模式动作方向位和 0x12/0x17 完成判断、可用速度和安全位置范围。还需独立抓取一组请求/应答/运行上报/完成上报帧及 CRC 参数。缺任一关键参数时不允许运动实发。CRC 若算法未确认也不能把模拟测试结果称为真实设备闭环。

## 实施与验证记录（2026-09-28）

* 已实现带 SHA-256 版本的 JSON 配置、原子导出、显式启用与在途快照；ASCII 数字模板、二进制定长/长度字段及 DT 专用整帧解析；常量、字段、枚举、线性换算与位域映射；趋盛 0x11 绝对运动和 0x12 查询编解码；上下游双串口、手动预览、模拟回告解码、字段/映射表格编辑。
* 请求管理区分写出、0x11 接纳和 0x12 核查完成。0x17 只作为无序号状态上报处理；发送、应答、运动完成有三个独立超时。取消不下发停止，运动不自动重试。8 位序号一连接内用尽后拒绝继续发送。
* 在 Windows Qt 5.14.2 MinGW 32 位下实际完成应用和测试工程构建。Qt Test 12 项通过：双格式等价和重载、原演示分帧回归、定长/长度字段、小大端与 CRC、校验失败、舍入/枚举/位域、DT 整帧语法与应答、序号耗尽、0x11 与完成分离、写出停滞、设备拒绝及断线。离屏启动烟测运行 2 秒未退出。
* **尚未完成真实设备验收**：无独立抓包样例及已确认的设备档案，不能证明 CRC 及 0x11/0x12/0x17 与实体固件一致。未接真实上、下游串口，未验证物理方向、行程、超时值、压力和失步行为。示例地址、速度、位置比例是纯预览占位值，三个确认标志均为 `false`。DT 设备错误到状态字的映射也未确认，真实 DT 发送另有独立锁定。
* 当前范围不含 TCP、复杂变长嵌套结构、动作编排、相对运动、可编辑趋盛目标帧，以及动态字段的二进制响应模板。二进制示例使用固定回告字节。上述后续接口的语义不能从试验代码推断。
