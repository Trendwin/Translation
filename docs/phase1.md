# 第一阶段范围、依据与验收

## 已实现范围

- 中文界面编辑 ASCII/HEX、帧头、帧尾和有顺序的字段表。
- 中文界面编辑客户命令码、绝对位置操作、响应方式和位置关系。
- JSON 导入、导出、校验、显式启用，以及草稿/启用版本分开显示。
- 通用完整帧解析、半包、粘包、噪声和 4096 字节缓存上限。
- 绝对位置统一命令和受限趋盛 0x11 编码。
- 单一趋盛串口发送、0x11 应答、0x12 完成查询、超时、拒绝、断线和迟到帧处理。
- 离线预览和设备回告帧校验。

## 协议依据与冲突处理

趋盛帧使用 AA AA 帧头、目标/源地址、长度及反码、8 位序号、命令、数据和 CRC16。0x11 绝对位置数据使用 DevID、绝对位置模式/动作、24 位大端速度和 24 位大端目标位置。

HMD6 手册中的 DT 行为只用于制作示例输入配置。现有试验代码曾把 DT 当成内置语法并生成固定客户回告，该行为已移除。程序现在不解释 DT 大小写、Q 或客户回告格式；如果后续需要完整 DT 产品支持，应继续由配置或明确扩展接口描述，不能重新放入通用解析器分支。

## 自动验收

- 同一个通用解析器从配置解析 DT 风格示例。
- 修改帧头、帧尾和命令码后无需改 C++。
- 两种 ASCII 配置生成等价趋盛帧。
- 缺少帧头、帧尾错误、字段长度错误、未知命令、非数字和越界均被拒绝。
- 大端、小端、线性换算、保存重载、半包、粘包、噪声和缓存上限受检。
- 趋盛目标帧与记录样例一致。
- 写出停滞、设备拒绝、断线、迟到帧以及命令应答和动作完成的区别受检。
- 运行界面源码只创建一个设备串口传输对象。

## 真实设备前仍需确认

示例中的目标地址 2、源地址 1、DevID 0x11、动作值 1、速度 1000 μm/s、行程 0–60000 μm，以及客户位置乘 10 得到微米，尚未通过本仓库内可复核的实机记录确认。必须由设备负责人确认后才能勾选界面确认项。还需用真实控制板核对串口参数、0x11 错误码、0x12 状态字和动作完成时序。

## 后续建议

下一阶段优先增加经设备验证的更多命令模板和查询展示，再评估长度字段、客户 CRC、TCP、复杂字段结构和可编辑目标模板。每一种能力都应先补配置校验和独立报文样例。

## 本轮验证记录（2026-10-09）

Windows 本机使用 Qt 5.14.2 / MinGW GCC 7.3.0 32 位工具链成功构建应用及两套测试。核心测试：17 个功能用例通过（Qt Test 总计 19，含初始化/清理）；界面测试：3 个用例通过（总计 5，含初始化/清理），未失败、未跳过。界面以 offscreen 平台配合 Windows 字体渲染并逐页查看，英文 JSON 键仅留在高级配置，ASCII/HEX 和 DevID 等协议标识保持原样。

新增覆盖非法转义、非法数值配置、固定值/直接引用/正负线性换算、舍入/整数溢出、带帧尾字节的固定长度二进制帧、应答/运动超时、取消后的状态恢复，以及未保存表单和未应用 JSON 不能继续使用旧草稿的界面流程。自动测试未接入真实串口或控制板，不能替代实机对 CRC、字段单位、动作值和回告时序的验证。

首版设备状态查询是运动状态恢复工具，不新增客户命令模板。复杂客户协议能力仍在阶段范围之外。
