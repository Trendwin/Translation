# ASCII 文本按原样匹配

选择“ASCII 文本”后，帧头、帧尾、字段分隔符、固定文字和手动报文都按输入的 ASCII 字符原样处理，不再解释反斜杠转义。上游接收也不改写报文字节。

| 填写内容 | 实际匹配的字节 | 字节数 |
| --- | --- | --- |
| `\n` | `5C 6E` | 2 |
| `\r\n` | `5C 72 5C 6E` | 4 |
| `\t` | `5C 74` | 2 |
| `\x20` | `5C 78 32 30` | 4 |
| `&` | `26` | 1 |

单个反斜杠、末尾反斜杠和 `\z` 等文字同样合法；超过 ASCII 范围的字符仍会报错。数值字段仍严格按十进制解析，数字列表仍按逗号拆分。

## 发送与配置示例

帧头填写 `@&`，帧尾填写 `\r\n`；延时字段设置“普通字段”“无符号整数”“读到分隔符”，分隔符填写 `\n`。上游在普通 ASCII 模式原样发送：

```text
@&5A&01&SCT&1&0;MFCV=255;10\nEND&?&\r\n
```

这是 39 字节，`10` 后面是 `5C 6E`，末尾是 `5C 72 5C 6E`。关闭串口助手的“解析转义字符”和“自动追加回车换行”，避免改变报文。相同文字可直接粘贴到软件“手动调试”中解析、预览。上游接收使用已保存格式；修改格式后先保存配置。

应提取命令 `MFCV`、参数 `[255]`、延时 `10`。等待标志和延时配置为普通字段，只解析，不执行等待。已有 `execution` 角色的拒绝发送保护仍保留；校验值仍只提取、不验证算法。

可导入 [ASCII 原样顺序格式示例](../examples/literal-ascii-sequential.json) 进行离线解析和转换预览。示例映射仅用于展示配置方式，实际设备与阀路关系需按现场配置。上游接收页仍只接收，不会自动向下游发指令。

## JSON 与已有配置

JSON 文件本身的反斜杠必须按 JSON 规则写。例如界面填写的两个字符 `\n`，在 JSON 中写为 `"\\n"`；四个字符 `\r\n` 写为 `"\\r\\n"`。导入后软件不再做第二次反斜杠解码。导出、保存和重启保持这些字符及其他映射、扩展数据。

已有 ASCII 配置中的 `\n`、`\r` 等可见写法现在按字面匹配，无需重建映射。如果旧配置原本依赖把这些写法还原成真实控制字符，需要重新核对其线上字节。HEX 编码规则保持不变，可用 `0A`、`0D0A` 表示真正的换行、回车换行；不自动兼容猜测两种帧尾，也不在收到数据后自动替换字符。
